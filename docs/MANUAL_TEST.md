# Check the real Google Photos integration

Use an album you own with a few photos before testing a large album. User testing confirmed installation, the toolbar and saved picks, and identified K as a native navigation shortcut. Version 0.1.3 uses a browser command with default Alt+Shift+S; verify its binding in Chrome. The cloud browser's managed policy blocks installing unpacked extensions.

1. Load `extension/` unpacked in desktop Chrome or Edge. Confirm no errors on its extension card. Refresh Google Photos and open a regular album.
2. Confirm the panel appears in regular and shared `/share/…` album grids and photo viewers, and disappears on the main photo feed. For a shared photo, test opening its link directly and refreshing the viewer; the toolbar should appear without first visiting the album grid. Confirm the popup shows v0.1.3 or newer.
3. Open a photo full-size. Keep it, move to another photo with the native arrow keys, and confirm simply viewing the second photo does not keep it. Use K and confirm native backward navigation still works. Keep a second photo with Alt+Shift+S, then toggle it off and on again without navigating. Click a native Next button and verify the keep shortcut still works while that button retains focus.
4. Confirm the keep shortcut does not fire while typing in a caption/comment field. Disable the shortcut in How it works and confirm the button still works. Check Tab navigation, visible focus, and the collapsed panel. Remap the command in Chrome’s extension shortcut settings and confirm the panel and popup show the new binding. Clear its binding and verify the UI asks for an assignment while the button remains usable.
5. Refresh the viewer. Confirm the shortlist survives. Review its links and verify they reopen the same original photos. Open another album and confirm its shortlist is separate.
6. Return to the grid with **no existing native selection**. Select kept photos. Check both the extension’s result and Google Photos’ selection count; visually confirm the selected tiles are the photos you kept. If no controls can be recognized, save the error text and report the browser version and interface language. Do not share cookies, tokens, or private photo URLs.
7. Manually choose Google Photos’ Add to album and select a test destination. Confirm the expected photos are there and the source album is unchanged.
8. Test an album with enough photos for Google Photos to virtualize thumbnails. Keep photos near the beginning, middle, and end. Confirm all three select correctly, without extras.
9. Start a larger scan and stop it. Confirm no further photos become selected. Clear the native selection and retry.
10. Test a missing photo (keep a photo, then remove it from the source album through Google Photos). Confirm the extension reports a partial result and does not claim all photos were selected.
11. With an unrelated photo already selected, including one scrolled out of view, confirm the extension asks you to clear Google Photos’ selection before proceeding.
12. Clear the local shortlist, undo it, and confirm neither operation changes Google Photos’ native selection. Clear it again after completing the destination album.
13. In a shared album, confirm Review shortlist links reopen the same photos with the current access key. Keep photos, return to its grid, and try selecting them. If Google Photos does not offer native selection controls in that shared view, confirm the extension reports the limitation and preserves the shortlist instead of claiming success.
14. Try selecting kept photos with the mouse away from all thumbnails. Confirm native controls that are hidden until hover can still select the right photos and the reported native count matches.
15. If selection fails, hover over a thumbnail for a moment, then use Check page layout in the error message. Inspect the report and confirm it contains counts and structural metadata, without URLs, photo IDs, captions, access keys, or raw HTML. Copy it (or use the selected text fallback) to share with the developer. Verify no native selections or shortlist entries change when generating the report.

If viewer IDs and tile IDs differ, or controls are not exposed in a supported shape, the DOM adapter needs a code change. Do not work around this with guessed selectors, session extraction, or undocumented Google API requests.
